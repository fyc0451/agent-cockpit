# Local Project Discovery v1

## Boundary

PROJ-002 supplies a read-only Local discovery kernel. It does not expose HTTP
routes, initialize or write Project Registry, mutate the Files root allowlist,
or create Project, RepoLocation, Workspace, Run, Agent, pane, branch, worktree,
Mail identity, or operation.

The implementation is split into:

- `project_discovery.py`: immutable values, stable errors, canonical JSON, and
  versioned SHA-256 fingerprints;
- `project_discovery_service.py`: Local allowlisted-root resolution, direct
  directory listing, bounded read-only Git observation, and an injected
  Registry match read port.

PROJ-004 owns API envelopes, HTTP status mapping, registration, idempotency,
and the second discovery used to validate `expected_discovery_fingerprint`.

## Locator

The only v1 locator is:

```json
{"node_id":"local","root_id":"root_<opaque>","path":""}
{"node_id":"local","root_id":"root_<opaque>","path":"relative/directory"}
```

`root_id` is generated by the server from an allowlisted Local root. A client
cannot submit a root absolute path. An explicit `path=""` selects exactly the
allowlisted root identified by that opaque `root_id`; it never means the system
root, a missing value, or a normalized spelling of another path. A non-empty
`path` is canonical POSIX-relative text. Absolute paths, `~`, `.`, `..`, empty
components within a non-empty path, trailing slash, backslash, NUL, controls,
missing paths, and non-directories are rejected.

Every operation opens the current allowlisted root and traverses each target
component with descriptor-relative, no-follow directory opens. Listing and Git
commands remain bound to that target descriptor for the complete operation;
pathname re-resolution is only an additional stale check. Symlink escapes, root
replacement, target replacement, swap-and-restore, and stale root IDs fail
closed. Directory listing includes only direct real
directories; it does not recurse or follow symlink entries. Every entry always
contains `registered_project`, either an exact active `(node_id, canonical_path)`
match or explicit `null`. Listing also exposes `complete`, inverse `partial`,
successful `sources`, and stable `warnings`. Any Registry lookup failure — total
or partial/mixed — retains Local entries but sets `partial=true`, omits
`project_registry` from successful `sources`, and reports
`project_registry_unavailable`; `project_registry` appears in `sources` only when
every entry lookup succeeded. Under that partial state a null match is unknown,
not proof that the directory is unregistered. Each child identity is rechecked
after Registry lookup so a replacement cannot inherit stale match evidence.

Stable discovery errors are:

- `invalid_locator`
- `root_forbidden`
- `node_not_found`
- `capability_unavailable`
- `discovery_unavailable`

Errors contain only the code, never a filesystem path, Git remote, stderr, SQL,
or payload. Sanitized errors suppress cause and context so generic traceback
formatting cannot recover the original exception text.

## Result

The public result contains the normalized locator, safe display path,
`canonical_path_digest`, VCS observation, exact and possible Project matches,
`discovery_fingerprint`, observation time, completeness, sources, and stable
warnings. The raw canonical path is available only as an explicit trusted
application-service property and is excluded from public serialization. `sources`
names only the data sources that produced evidence for this result
(`local_files`, `local_git`, and on success `project_registry`); a Registry
failure degrades the result to `complete=false`, clears matches, reports
`project_registry_unavailable`, and omits `project_registry` from `sources`.

`exact_match` means an active Registry RepoLocation has the same
`(node_id, canonical_path)`. `possible_projects` is an advisory repository
identity match. It never merges or attaches a Project. Non-Git directories do
not produce repository matches. The service discards any impossible repository
suggestions returned for a non-Git observation while preserving an exact active
path match.

The accepted Registry Store does not yet expose match queries. PROJ-002 uses a
read-only `RegistryMatchReader` Protocol and test fake. Without a real adapter,
the default reader marks the result incomplete with
`project_registry_unavailable`; it never reports an empty complete match set.
No discovery module opens Registry SQLite or contains SQL.

## VCS observation

Non-Git directories are a complete valid result with `vcs.kind="none"`.
Selected Git paths must be the Git top-level in v1. A selected subdirectory of
a larger checkout is rejected even when its allowlisted ancestor can be selected
with `path=""`, preventing multiple RepoLocations for one checkout.

Git observation uses a trusted absolute executable and an allowlisted child
environment, argv execution with stdin disabled, an aggregate stdout+stderr
limit, timeout, UTF-8 strict decoding, `--no-optional-locks`,
`GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `core.fsmonitor=false`, and a
stable C locale. It observes:

- canonical Git top-level;
- full HEAD, branch-presence only, detached/unborn state;
- porcelain status, exposed only as dirty plus a digest;
- optional origin, exposed only as a normalized fingerprint;
- local branch/tag count and a digest over sorted ref names and targets; raw ref
  names are not included in the public result;
- root-commit repository fingerprint when no origin exists;
- optional upstream-presence and ahead/behind counts; raw upstream is internal
  only and is never public.

Timeout, permission failure, malformed/oversized output, and inconsistent Git
answers are `discovery_unavailable`, not non-Git. Discovery never fetches,
checks out, resets, cleans, updates configuration/index, or changes refs.
Every subprocess runs in a dedicated process group; timeout and output-limit
cleanup kills and reaps that group so descendants cannot outlive discovery.
For a confirmed Git directory, two bounded complete observations of top-level,
HEAD/branch, status, remote, refs/history, and upstream must be identical.
Otherwise discovery fails closed rather than returning a mixed-generation
fingerprint. Non-Git requires only the initial read-only top-level probe.

## Fingerprint

All fingerprints are `sha256:<64 lower hex>` over sorted-key compact ASCII
canonical JSON. `discovery_fingerprint` v1 binds:

- locator and canonical path digest;
- root and target identity;
- complete VCS observation and status/refs digests;
- exact match and sorted possible Project IDs;
- completeness and stable warnings.

It excludes `observed_at`, display labels, absolute path text, raw remote URL,
raw status filenames, and ordering accidents. Unchanged evidence produces the
same fingerprint. HEAD, dirty/status, remote/repository identity, refs, path
identity, match evidence, or completeness changes it.

## Zero-side-effect gate

Roots, listing, and discovery perform no writes to Registry, Mail, Herdr,
Coordination, tasks, settings, custom roots, runtime stores, Git state, or user
directories. They do not create SQLite/WAL/SHM files, use a shell, access the
network, fall back a non-Local node to Local, or start any runtime object.

Tests use only temporary roots and repositories and verify filesystem/Git
evidence before and after discovery.
